## 1. 合约总览

| 项 | 值 | 说明 |
| --- | --- | --- |
| 源文件 | `contracts/TeachingTrace.sol` | 通用 solc 0.4.26 可编译（`pragma solidity ^0.4.20`，无任何蚂蚁链扩展） |
| 合约名 | `teaching_platform_v1` | 合约地址由合约名 SHA256 派生，部署与调用必须同名（01 方案 7.2 节） |
| 目标链 | 蚂蚁链开放联盟链 `a00e36c5`，REST 网关 `https://rest.baas.alipay.com` | 01 方案 7.2 节 |
| 调用账户 | KMS 托管账户「陈以宁」，地址 `bd6d0c49…` | 平台代签（本地仅握手换 token） |
| 事件 | `event LOG_STRING(string)` | 载荷即 miniappinfo JSON（见第 6 节） |
| 链上状态 | `achievements`（成果表）、`records`（活动记录表）、`creditOf`（学分表） | 见第 7 节存储速查 |
| 合约间调用 | **无**（单合约） | 交互关系指「合约 ↔ REST 通道 ↔ 平台后端 ↔ 各校/教育局」的调用时序，见第 5 节 |
| 状态特征 | 无 require/assert、无转账与扣款逻辑 | 错误与回滚语义见第 8 节 |

三个入口契约一页速览：

| 入口 | 签名 | 性质 | 输出 |
| --- | --- | --- | --- |
| 教研成果确权存证 | `registerArtifact(string, string, string, string, string)` | 写交易 | `LOG_STRING`（miniappinfo：成果编号/标题/作者/学校/文件哈希 五项） |
| 教研活动参与记录 | `recordActivity(string, string, string, string)` | 写交易 | `LOG_STRING`（miniappinfo：活动编号/教师/学校/贡献分钟/折算学分 五项）；同时累加教师学分 |
| 教师累计学分查询 | `getCreditFor(string)` | view 本地只读 | `returns (string)` 累计学分十进制串 |

**通用约定**（三入口一致，不再逐项重复）：

1. **参数全部是 string**：REST 通道直接以字符串数组传参（如 `["ART-2026-001","跨校集体备课案例：二次函数教学设计","周书","成都理工大学工程技术学院","0a9999…64位"]`），
   避开 bytes32 传参必须写成 32 个十进制数字嵌套数组的实测坑（01 方案 9 节"参数编码注意"）。
2. **合约返回值与链上元数据的区分**：`registerArtifact`、`recordActivity` 在合约签名层面**没有返回值**
   （`txHash`/区块号/链上时间戳/gasUsed 这些"存证编号与时间戳"来自**交易回执**，由通道返回，不是合约 returns —— 对应 01 方案 5.3 节"链上元数据带"）。
3. 中文文本使用 UTF-8 编码，链上按字节原样保存；事件载荷中的中文键名照原样输出。

## 2. 入口一 `registerArtifact` —— 教研成果确权存证

**签名**（冻结，参数顺序不得变动）：

```solidity
function registerArtifact(
    string artifactId,   // 成果编号
    string title,        // 标题
    string author,       // 作者
    string school,       // 学校
    string fileHash      // 文件哈希
) public
```

**参数表**：

| 参数 | 类型 | 含义 | 必填 | 示例 |
| --- | --- | --- | --- | --- |
| artifactId | string | 成果编号，平台业务主键，形如 `ART-YYYY-序号`，建议全链唯一 | 是（可为空串，按 8.2 语义原样存证） | `ART-2026-001` |
| title | string | 教研成果标题（教案/课件/课例/纪要/诊断报告） | 是（同上） | `跨校集体备课案例：二次函数教学设计` |
| author | string | 第一作者 — 署名权主体（确权主体） | 是（同上） | `周书` |
| school | string | 作者所属学校 — 确权归属校 | 是（同上） | `成都理工大学工程技术学院` |
| fileHash | string | `SHA-256(成果文件原文)` 的 64 位十六进制小写；链上只存哈希不存文件本体 | 是（同上） | `0a9999…（64 位十六进制）` |

**返回值**：无（合约签名无 returns）。链上产物为：
- 一笔合约交易（回执含 txHash / 区块号 / 链上时间戳 / gasUsed —— 平台以此 txHash 作为该成果的**唯一存证编号**）；
- 一条 `LOG_STRING` 事件，载荷即该成果的 miniappinfo JSON（格式见第 6 节示例 A）。

**核心逻辑**（与合约逐行对应，源码行内注释已述及，此处复述评审视角的算法）：
组装 `Artifact` 结构体 → `achievements[artifactId] = a` 落库（**同编号重复登记 = 覆盖更新**）→
`tableLogArtifact` 严格"先写状态、后发日志"，保证事件载荷 = 本次调用的最终链上状态。

## 3. 入口二 `recordActivity` —— 教研活动参与记录与学分折算

**签名**（冻结，参数顺序不得变动）：

```solidity
function recordActivity(
    string activityId,     // 活动编号
    string teacherId,      // 教师
    string school,         // 学校
    string effortMinutes   // 贡献分钟数
) public
```

**参数表**：

| 参数 | 类型 | 含义 | 必填 | 示例 |
| --- | --- | --- | --- | --- |
| activityId | string | 教研活动编号，形如 `ACT-YYYY-序号`（活动维度主键） | 是 | `ACT-2026-001` |
| teacherId | string | 教师唯一标识，跨校通用（学分账户键） | 是 | `陈以宁` |
| school | string | 教师本次活动所属学校（仅记录字段，不构成写权限区分） | 是 | `成都理工大学工程技术学院` |
| effortMinutes | string | 贡献分钟数原始字符串（发言/参与时长统计口径，由会议纪要统计件产出） | 是 | `90` |

**返回值**：无（合约签名无 returns）。链上产物为：
- 一笔合约交易（回执同入口一，txHash 即该参与事实的唯一存证编号）；
- 一条 `LOG_STRING` 事件，载荷即该参与记录的 miniappinfo JSON（格式见第 6 节示例 B）；
- **同一次调用内的状态变更**：`creditOf[teacherId] += credit`（教师学分账户累加）。

**折算算法**（01 方案 7.4 节固化，源码 `recordActivity` 与 `strToUint` 注释逐行对应）：

```
m = strToUint(effortMinutes)      // ASCII 逐字符校验 '0'~'9' 并累加：result = result×10 + 位值
                                  // 校验失败（空串/含非数字字符）→ m = 0（01 方案 7.5 定版）
credit = m × 2                    // 统一折算口径：贡献 1 分钟 = 2 学分（写死在合约内，跨校一致即互认）
creditOf[teacherId] += credit     // 仅增不减
records[activityId + "|" + teacherId] = Record{...}   // 复合键留痕：同活动多教师各存一条
emit LOG_STRING(重点:即为该条记录的 miniappinfo)       // lists 内「折算学分」= 本条的 credit（非累计）
```

示例：`ACT-2026-001` + `陈以宁` + `90` 分钟 → 本条折算 `180` 学分，`creditOf["陈以宁"]` 累加 180。

## 4. 入口三 `getCreditFor` —— 教师累计学分查询（本地只读）

**签名**（冻结）：

```solidity
function getCreditFor(string teacherId) public view returns (string)
```

**参数表**：

| 参数 | 类型 | 含义 | 必填 | 示例 |
| --- | --- | --- | --- | --- |
| teacherId | string | 教师唯一标识（学分账户键，与 recordActivity 参 2 同口径） | 是 | `陈以宁` |

**返回值**：`string` —— `creditOf[teacherId]` 的十进制字符串表示，例如一次 90 分钟活动后返回 `"180"`；
两次不同学校的活动（如 90 分钟 + 60 分钟）后返回 `"300"`（90×2 + 60×2）。

**读取语义**：
- `view` 只读：经 REST 本地只读通道调用（`CALLCONTRACTBIZ` + `isLocalTransaction:true`），**不打包、不耗 gas、不改变链上任何状态**（写入佣金无）；任意学校教师端、教育局审计端都能直接查。
- 从未参与过任何记录的教师：mapping 缺省值 0 → 返回 `"0"`（`uintToStr(0)` 的分支在源码中单独注释）。
- **诚实边界（待实测项）**：本地只读通道本身已有 `uint8` 出参返回实测先例（`docs/REST通道接入说明.md:158-173`），
  但 **string 类型出参无实测先例**，为首笔部署后的待实测项目（01 方案 9 节第 6 行）；部署后首测 `outTypes:["string"]` 返回是否为 `"180"` 进过程实录。

## 5. 合约间交互关系与调用时序

`teaching_platform_v1` 是**单合约实现**：内部没有 contract → contract 调用（没有任何跨合约 import/委托调用），
三个入口彼此独立、通过三张 mapping 共享状态（`recordActivity` 写 `creditOf`，`getCreditFor` 读 `creditOf`）。
因此本节的"交互关系"按大赛要求（`00-大赛要求.txt:29`）规范为 —— **本合约与平台其他部分（REST 通道、平台后端、
各校教师端、教育局审计端）之间的调用时序**，覆盖 01 方案第 2 节架构图中的四条连线与第 9 节第 3~7 行的六类调用。

### 5.1 部署时序（01 方案 9 节第 3 行）

```
平台后端(TeachFlowTool deploy 子命令)
  │ 1. REST 握手：accessId + 毫秒时间戳 → SHA256withRSA 签名 → shakeHand 取得 30 分钟 token
  │ 2. 交易组装：from=托管账户「陈以宁」+ mykmsKeyId（平台 KMS 代签）
  ▼
REST 网关 rest.baas.alipay.com
  │ 3. DEPLOYCONTRACTFORBIZASYNC，contractCode = build/contracts/TeachingTrace.bin
  ▾
开放联盟链 a00e36c5 —— 合约 teaching_platform_v1 落链（地址 = 合约名 SHA256 派生）
  │ 4. 回执：部署交易 txHash / gasUsed
  ▼
平台后端记录部署凭证（后续所有调用都以 teaching_platform_v1 为 contractName）
```

### 5.2 成果存证时序 —— `registerArtifact`（教师/AI 产物上链）

```
教师端(或 AI 层模拟件产出纪要/诊断报告文件)
  │ 1. 平台后端计算 fileHash = SHA-256(文件原文)（HashUtil 同款算法，链下）
  │ 2. 教学数据归约：五个 string 参数（含 64 位哈希）
  ▼
平台后端 —— CALLCONTRACTBIZASYNC 调 registerArtifact(string×5)
  ▼
合约：写 achievements[artifactId] → emit LOG_STRING(miniappinfo) → 返回
  ▼
平台后端取回执（txHash/区块/时间戳/gasUsed），txHash 即该成果唯一存证编号；记录台账
  ▼
各校/教育局：QUERYTRANSACTION 按 txHash 查回执 → 解 LOG_STRING 载荷比对五字段；
手机原文重算 SHA-256 与链上 fileHash 比对 → “何时、谁、在何校、产出了什么内容”独立可验
```

### 5.3 活动参与时序 —— `recordActivity`（贡献留痕 + 学分互认）

```
教研活动结束（会议纪要统计件产出各教师贡献分钟，本机为模拟件）
  │ 1. 平台归约出 activityId/teacherId/school/effortMinutes 四个 string
  ▼
平台后端 —— CALLCONTRACTBIZASYNC 调 recordActivity(string×4)
  ▼
合约（同一次调用内原子完成）：
   strToUint(effortMinutes) → credit = m×2 → creditOf[teacherId] += credit
   → records[activityId|teacherId] 留痕 → emit LOG_STRING(miniappinfo)
  ▼
平台后端取回执 → 台账；教师端/主管端随后用 getCreditFor 只读查询累计学分（5.4）
```

### 5.4 学分查询时序 —— `getCreditFor`（只读，无交易）

```
教师端 / 教育局审计端
  │ 1. 请求“某教师累计学分”
  ▼
平台后端 —— CALLCONTRACTBIZ + isLocalTransaction:true 调 getCreditFor(teacherId)
  ▼
合约本地执行：uintToStr(creditOf[teacherId])，按 outTypes ["string"] 返回（出参形态为待实测项，见第 4 节）
  ▼
平台后端把字符串交回前端：跨校同值 —— 同一教师在任意联盟校参与活动的学分都进同一个 creditOf 账户
```

### 5.5 审计追溯时序（01 方案 4.4）

```
教育局（只读角色，零写权限）
  │ 1. 持有 txHash → QUERYTRANSACTION / QUERYRECEIPT 取回执与原文（data 为 base64，解码即原文）
  │ 2. 原文重算 SHA-256 ↔ 链上 fileHash 比对（无需信任平台数据库）
  │ 3. getCreditFor 汇总 ↔ 逐笔 recordActivity 回执复算（分钟×2 求和）比对
  ▼
结论：审计口径 = 证据口径（链上原始交易而非平台报表）
```

## 6. `LOG_STRING` 事件与 miniappinfo 载荷格式

两个写入口各触发 `LOG_STRING` **一次**，载荷是同一个骨架（与已实测的 `BabyTraceCompat` tableLog 同构，
`contracts/BabyTraceCompat.sol:142-160`），逐键说明如下：

| 键 | 取值 | 说明 |
| --- | --- | --- |
| `__type__` | `"miniappinfo"` | 展示格式标记：蚂蚁链浏览器/小程序据此解析渲染（模板约定，值固定） |
| `prevHash` | `""`（恒空串） | 冻结 ABI 无 prevHash 入参位（01 方案 7.3 条款 2）；教研时序溯源靠**交易本体**（txHash/区块/时间戳天然有序），不靠哈希指针链 |
| `nextHash` | `""`（恒空串） | 同上 |
| `lists` | 5 个展示项数组 | 每项为三键对象 `{"name":字段中文名,"value":字段值,"type":"text"}`；字段中文名与顺序见两示例 |

**示例 A — `registerArtifact` 触发**（values 即调用方的入参原样，键名顺序 = 合约 `tableLogArtifact` 内顺序）：

```json
{"__type__":"miniappinfo","prevHash":"","nextHash":"","lists":[{"name":"成果编号","value":"ART-2026-001","type":"text"},{"name":"标题","value":"跨校集体备课案例：二次函数教学设计","type":"text"},{"name":"作者","value":"周书","type":"text"},{"name":"学校","value":"成都理工大学工程技术学院","type":"text"},{"name":"文件哈希","value":"0a9999…（64 位十六进制小写）","type":"text"}]}
```

**示例 B — `recordActivity` 触发**（`贡献分钟` 为原始入参字符串；`折算学分` 为合约计算值 `uintToStr(m×2)`，是本条折算值而非累计值）：

```json
{"__type__":"miniappinfo","prevHash":"","nextHash":"","lists":[{"name":"活动编号","value":"ACT-2026-001","type":"text"},{"name":"教师","value":"陈以宁","type":"text"},{"name":"学校","value":"成都理工大学工程技术学院","type":"text"},{"name":"贡献分钟","value":"90","type":"text"},{"name":"折算学分","value":"180","type":"text"}]}
```

**事件与状态的一致性**：事件永远在状态写入之后发出（先写后日志），故载荷内容 = 本次调用的最终链上状态；
审计以事件为展示口径、以交易回执为证据口径，两者同源同值。

## 8. 错误与回滚语义（本实现的简化口径，01 方案 7.5 定版）

**设计取向**：本版与 `BabyTraceCompat` 同策略 —— **不用 `require` 做扣款/断言式校验**。
业务输入校验属于平台侧职责；链上的职责是把“发生的事实”原样固化，包括异常输入本身（审计要能看到异常）。

| 情形 | 行为（全部实测口径出自 01 方案 7.5 与合约注释，本文转述） | 是否回滚 |
| --- | --- | --- |
| `effortMinutes` 为**空串**或含任一非 `'0'~'9'` 字符 | `strToUint` 返回 0 → 折算 0 学分；记录**照常留痕**（原始分钟串原样保存在 `effortMinutes` 字段并照常 emit） | 否（不 require、不回滚） |
| 合法数字串（如 `90`、`009`） | 按十进制解析（前导零无影响），`m×2` 折算并累加 | — |
| `registerArtifact` 收到空串/任意长度字符串 | 原样存证（包括 `achievements[""]` 这样键为空的极端情形），链上不拒绝任何字符串 | 否 |
| 同 `artifactId` 再次 `registerArtifact` | 覆盖更新：后登记内容替换先登记内容（链上一键一最新值） | 否 |
| 同「activityId\|teacherId」重复 `recordActivity` | 记录被覆盖、**学分再次累加**（重复计分）。合约语义 = "每次调用是一次参与事实"；幂等去重、防重复提交由平台侧业务主键控制 | 否 |
| `getCreditFor` 查未参与教师 | 返回 `"0"`（mapping 缺省值），无副作用 | — |
| 超长"数字串"（数十位以上） | solc 0.4 无溢出检查，`result×10` 静默回绕按低 256 位取值——业务量级（贡献分钟）走不进该区间，合约不额外设防（源码 strToUint 注释已注明） | 否 |
| 状态更新中途的任何执行失败（如 OOG 耗尽 gas） | EVM 事务语义：**整笔交易原子回滚**，状态变更与事件全部不生效，回执失败码可见——这是事务性保障，不是 require 提供 | 是（EVM 层） |

**权限与扣款说明**：
- 合约无 `payable`、无转账、无余额扣减逻辑，"gas 扣款"只发生在通道侧记账（平台托管账户 fuel），合约内无任何资金语义。
- 写入口无显式权限校验：现阶段全部写交易由 KMS 托管账户「陈以宁」平台代签发起，**谁能调用写方法 = 谁能通过平台通道**；
  school/teacherId 只是记录字段。规模化生产需各校独立账户自行签名（诚实声明，01 方案 7.5 节尾款）。
